# K4-2 (blocker) — spec §5.1(1) under-fixes `seeds::build` enumeration: nest order and weak monotonicity

Artefact: `work/10-recreate/spec/interfaces.md` §5 item 1 ("enumerates `(a,b,c,d,e)`
in nested ascending loops"); source `.scratch/gh/upstream/seed.cpp:85-90`.

Spec says "nested ascending loops" over (a,b,c,d,e) and never says which
coordinate is the outer loop or that the tuples are weakly increasing. Source is

  F(e,n) F(d,e+1) F(c,d+1) F(b,c+1) F(a,b+1)   // e outermost, a innermost
    if(a>e-d+1) continue;                       // = (2.7)
  i.e. a<=b<=c<=d<=e, a varies fastest, and the (2.7) filter is applied.

Reading the spec literally (a outermost, clip b>=a, ...) yields the *same set* in
a different order. That reverses the index t of most centres; `coverSeeds::run`
iterates t ascending and in each step inserts earlier centres into buckets, so t
order decides which pairs are already covered -> it changes the content of
`centers.txt`, not only its line order.

Settled from the recorded artefact (no rebuild):
  python3 - <<'P'
  N=0;bad=0;prev=-1
  for l in open('.scratch/gh/data/centers.txt').read().split('\n')[1:]:

      if f[4]<prev: bad+=1
      prev=f[4]
      if any(f[i]>f[i+1] for i in range(4)): bad+=1
  print(N,bad)
