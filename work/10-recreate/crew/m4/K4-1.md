# K4-1 (blocker) — spec §4 states the wrong bucket grid: K=3/m=38, code gives K=4/m=28

Artefact: `work/10-recreate/spec/interfaces.md` §4, row "bucket `K`, `m`";
source `.scratch/gh/upstream/covout.cpp:102-103`.

Spec: `max(1, int(R·n + .51)) = 3`, `m = ⌈n/K⌉ = 38`.
Source: `K=int(R*n+.51); K=max(1,K); m=(n+K-1)/K;`

Measured with R=.032, n=112: R·n = 3.584; int(3.584+.51) = int(4.094) = **K=4**;
m = (112+3)/4 = **28**. (m=38 is what K=3 would give, so the annotation was
evaluated by a different rule from the formula it prints.)

Settling test (4 lines, no build of the project):
  printf '#include <cstdio>\nint main(){double R=.032;int n=112;int K=int(R*n+.51);'
         'K=K<1?1:K;printf("K=%%d m=%%d\\n",K,(n+K-1)/K);}' > p.cpp
  g++ -O2 p.cpp -o p && ./p        # K=4 m=28

Why blocker: `covered()` scans the 3x3x3 bucket neighbourhood of index
(B.b[1]/K, B.b[2]/K, B.b[3]/K) (covout.cpp:90-93). m and K set the bucket
geometry, hence which pairs are found covered, hence `ncover`/`lp` and above all
`all.size()`. A coder who types the spec's numbers gets a 38^3 bucket grid and a
different `centers.txt` (header count, not just order) -> R2 fails for a reason
the spec caused. The formula is right; the printed value is wrong. Fix the value
(or say "evaluated by the code, not stated here").
