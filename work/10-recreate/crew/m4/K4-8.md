# K4-8 (minor) — `wrap` is not "into (-1/2, 1/2]": both endpoints are attained

Artefact: `spec/interfaces.md` §3.2 ("then `wrap`ped into `(-1/2, 1/2]` by
`nearbyint`"); source atlas.cpp:13 `inline double wrap(double x){return
x-nearbyint(x);}`.

nearbyint rounds ties to even, so 0.5 -> 0 and -0.5 -> -0. The map is onto
[-1/2, 1/2], closed at both ends; the half-open convention is the *other* one,
`x - floor(x + 0.5)`, which sends +1/2 to -1/2. Measured:
  printf 'nearbyint(0.5)=%g wrap(0.5)=%g wrap(-0.5)=%g wrap(1.5)=%g\n',
         nearbyint(.5), .5-nearbyint(.5), -.5-nearbyint(-.5), 1.5-nearbyint(1.5);
  -> 0 0.5 -0.5 -0.5

Why it is not nothing: `wrap` feeds `dephase`'s output (`dp`), `variants`,
`Atlas::find`'s deviation test and `relationB::init`'s cut. A coder who
implements the interval the spec states rather than the formula it quotes gets a
function that differs exactly on the ties, and the spec's whole reason for
existing is that such choices must not be left to the coder. State the
expression, not the range. Severity minor only because a tie is measure-zero in
`p`; the cost of fixing it is one sentence.
