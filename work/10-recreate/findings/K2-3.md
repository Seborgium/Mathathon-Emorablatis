# K2-3 — R2 acceptance checklist (for V)

Team K, member m2, direction k2. These are the guards from `K2-1.md` and `K2-2.md` as
assertions a `verify.sh` can execute. Each line names the finding it closes. Nothing here
changes the recorded run; all of it is harness-side. Copy or reject — but if a line is dropped,
`logs/R2.json` should say which and why, because each one closes a demonstrated false PASS.

Notation: `REF` = the manifest-pinned reference; `B` = this wave's build dir; `R` = a fresh run
dir. Everything absolute.

```
REF_SHA=c48bc9a2be1eb2cdeea82ea1b030d7cb9f00a6c9563b63f0248dd115748a5789
REF_SIZE=7339546
R2_REF_LINE=249878            # body lines
```

## Before the run

1. **Reference identity (H-4).** `REF` comes from `saved-run.manifest.json`, not from a glob.
   Assert `sha256sum $REF` = `$REF_SHA`, `stat -c %s $REF` = `$REF_SIZE`, and that
   `find "$(dirname $REF)" -name '*centers*'` returns exactly one path. Abort, do not warn.
2. **Manifest pin (H-5).** Assert `saved-run.manifest.json` `source.tree_sha1` =
   `ccba22651c54a8681de6f2fec2d96867445f2180`; record `git hash-object` of the manifest in the
   log. If `--check` was the mode used, say so in the log.
3. **Build provenance (H-1).** `test ! -e "$B"` before building; build with `build.sh`; then
   record `realpath`, `sha256sum`, `stat -c %Z` of `$B/covrun` and the sha256 of every source
   file it was compiled from. `$B` must be under a directory that did not exist at wave start.
4. **Reference not reachable from the run dir (H-2).** After seeding `$R`:
   `test -z "$(find "$R" -samefile "$REF")"` and `test -z "$(find "$R" -type l)"`.
   Seed with `cp --reflink=auto` only; never `ln`, never `ln -s`, never replay inside the cache.
5. **Output path (H-2, H-3).** `OUT=$R/centers.txt`; assert `realpath -m "$OUT"` ≠ `$REF`;
   `rm -f "$OUT"`; or run with `set -C` and rely on the O_EXCL failure.
6. **Negative control A — "no write" (H-6).** Build the one-line mutant
   (`if(getenv("MUT_A"))return 0;` after `covout.cpp:136`), run it through the *same* R2 path,
   require FAIL. 0.005 s. Catches: stale artefact, ignored exit status, missing-file handling.
7. **Negative control B — "wrong content, right shape" (H-6).** One-line mutant writing header
   `112 249878` and 249 878 lines of zeros; same path; require FAIL. 0.019 s, 5 247 447 B,
   249 879 lines. Catches: line-count-only comparison, stdout-grepping, content blindness.

## The run

8. **Timeout (H-3).** `covrun` takes ~402 s on this VM. Run with an explicit limit ≥ 900 s and
   record it; a wrapper that inherits a 25 s default gets a kill, not a verdict.
9. **argv.** Run exactly the recorded argv from the run dir: `cd "$R" && ./build/covrun centers.txt`.
   Do not add flags; `covrun` takes one argument and aborts on anything else (rc 134).
10. **Exit status.** Require rc 0 explicitly (`|| rc=$?`), never `;`.

## After the run

11. **Completeness before hashing (H-3).** `-f`, `stat -c %s` = `$REF_SIZE`, last byte is `\n`,
    `wc -l` = 249 879, every body line splits into 10 decimal fields with a trailing space.
    Only then `sha256sum`.
12. **Verdict.** `cmp -s "$OUT" "$REF"` **and** `sha256sum "$OUT"` = `$REF_SHA`; both, not either.
13. **Reference intact (H-2).** After the run, `stat -c %d:%i` and sha256 of `$REF` unchanged;
    `stat -c %s` of every cache file the run could have touched unchanged.
14. **Corroboration (H-7).** Parse our stdout: `N112 r0.0320 dual2 checked151744086 centers249878`
    must appear with those two numbers. Compare numbers, never bytes — the recorded
    `results/covrun.txt` is not reproducible from the published source and the shipped checker
    full-matches it.

## What `logs/R2.json` must contain

`ref_path`, `ref_sha256`, `ref_size`, `manifest_blob_id`, `tree_sha1`, `build_dir`,
`build_dir_created`, `binary_sha256`, `source_sha256{}`, `cmdline`, `cwd`, `started`, `ended`,
`rc`, `out_sha256`, `out_size`, `out_lines`, `controls:{A:FAIL|PASS, B:FAIL|PASS}`,
`verdict`. A wrong `controls` value is a FAIL of the rung, not of the code under test.

## What this checklist does not close

* The arithmetic contract at the two `pow(x,2)` sites (`K2-2.md` H-9) — that is R0's, and the
  probe has no `pow` test today.
* Which `centers.txt` R3 consumes. R3 says "our `arun` on the recorded `centers.txt`" and R6
  says "replay the DAG"; if R3 reads our R2 output the two claims are not the same and an R2
  defect silently changes R3's meaning. Record the sha256 of every input each rung opened, and
  state in `logs/R3.json` which of the two files it read.
* Whether our binary is bit-identical to upstream. It may be; that is not evidence of anything
  and must not be used as a check either way.
