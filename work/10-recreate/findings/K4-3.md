# K4-3 (major) — spec §2 `brun` omits that batch records are rewritten to radius = target

Artefact: `spec/interfaces.md` §2 `brun` ("batches `<prefix><n>.bin` of exactly
256 records"); source `.scratch/gh/upstream/stageB.cpp:300-310`.

The batch emitter does
  for(auto &z:dat){ z.radius=target; validate(z,target); }   // line 305
i.e. every record written to a batch carries radius := tau, not its achieved
radius, and is re-validated against tau. The spec never says this; §3.2's
record layout has a `radius` field and nothing else.

Manuscript agrees with the code, not the spec: §5.6 "(5.27) ... The radius
written for each Root is the common cap tau" and §7.2 "replacing each batch
radius by its target .016".

Settling test: first double of the tail 8 in any batch record.
  python3 - <<'P'
  import struct
  b=open('batches/f0.bin','rb').read(); n=struct.unpack('<Q',b[:8])[0]
  k=struct.unpack('<i',b[8:12])[0]
  off=12+36*8+36*8*k
  print(n,k,struct.unpack('<8d',b[off:off+64])[7])   # must print 0.016 exactly
  P
Why major: R5 compares batch files byte for byte. A spec-faithful implementation
writes the achieved radius (a different double almost surely) and every one of
the 88 batches differs, while `fine.bin` still matches — so the failure looks
like an ordering bug and sends the investigation in the wrong direction.
