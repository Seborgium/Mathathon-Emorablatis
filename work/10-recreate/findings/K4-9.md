# K4-9 (minor) — spec §1 names the wrong guard for two of the four files; taken literally it removes `brun`'s main

Artefact: `spec/interfaces.md` §1 ("each file hides its own `main` behind its own
guard (`#ifndef ATLAS_HEADER ... #endif`)"); sources as listed.

Actual guards around `main`, in order:
  seed.cpp:117   #ifndef HEADER           (defined by ub.cpp:1, covout.cpp:1)
  ub.cpp:368     #ifndef UB_HEADER        (defined by patchx.cpp:1)
  patchx.cpp:454 #ifndef PATCH_HEADER     (defined by atlas.cpp:1)
  atlas.cpp:216  #ifndef ATLAS_HEADER     (defined by stageB.cpp:1)
  stageB.cpp:283 #ifndef REFINE_HEADER    (defined by stageC.cpp:1)
  stageC.cpp:533 #ifndef STAGEC_HEADER    (defined by nothing)
So the parenthetical is true of atlas.cpp only: stageB's main is behind
REFINE_HEADER and stageC's behind STAGEC_HEADER, and neither name is mentioned in
the spec. A coder who follows the sentence literally and guards stageB's main
with ATLAS_HEADER — a macro stageB.cpp itself defines on line 1 — gets a `brun`
with no `main` at all, and the fresh-build rung fails at link time.

Settling test:
  for f in seed ub patchx atlas stageB stageC; do
    printf '%-9s ' $f; grep -n '#define [A-Z_]*_HEADER\|#define HEADER\|#ifndef [A-Z_]*HEADER' $f.cpp | tr '\n' ' '; echo
  done
and `g++ -std=gnu++17 -O3 stageB.cpp -o brun` after applying the spec's sentence
literally: undefined reference to main.
Fix: state the rule as "stageX.cpp defines the guard of the file it includes and
hides its own main behind `#ifndef <its own>_HEADER`", with the six names.
