# K4-4 (major) — covout's cover knobs that move `centers.txt` are absent from the spec, and the paper refuses to justify them

Artefacts: `spec/interfaces.md` §2 `covrun` ("Builds `seeds::build(112)`, covers"),
§4 row "cover radius `.032`, `dual = 2`"; source `.scratch/gh/upstream/covout.cpp:47-95`;
manuscript §A.3 last paragraph.

Four output-changing knobs are not fixed by the spec:
1. `dual` is not a flag: it is also the supdual iteration count
   (`supdual(k,A,B,dual)`, covout.cpp:85, loop `F(loop,iters)`), and it gates the
   whole LP path (`if(!dual || s-a > RN2) continue;`, line 83).
2. bucket reach is the +-1 index neighbourhood with the order constraint
   `j>=i-1, l>=j-1` (covout.cpp:91-93).
3. cheap accept `if(s+a+2.25 < RN2)` (line 82).
4. discard `if(s-a > RN2) continue` (line 83).

The paper cannot be the fallback: §A.3 says "The other square-power value T,
bucket reach, and integer cuts only select reuse attempts; missing an attempt
does not discard the current bin pair." That reasoning is about A's exclusions; in
covout a *missed* cover attempt inserts a new centre, so it enlarges the output.
These knobs are therefore load-bearing for R2 byte-identity while being
unjustified by the manuscript — the spec is their only possible source of truth.
