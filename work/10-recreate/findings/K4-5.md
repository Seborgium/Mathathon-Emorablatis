# K4-5 (major) — the comparators for R3-R6 exist only in the manuscript, and `commands.json` under-reports the artefacts

Artefacts: `.scratch/gh/upstream/commands.json`; manuscript §7.5 Tables 1-2;
`spec/interfaces.md` §2 `brun`; `work/10-recreate/gates.md` rows G-R2..G-R4.

1. Only `centers.txt` is cached locally (`.scratch/gh/data/`). The R3-R5 targets
   `coarse0..3.bin, mid.bin, fine.bin, fb1.bin` are not in the repository, so their
   *only* recorded comparators are the SHA-256 values in manuscript Table 2.
   Neither the spec nor `gates.md` names them. Verified now: the cached
   `centers.txt` hashes to
   c48bc9a2be1eb2cdeea82ea1b030d7cb9f00a6c9563b63f0248dd115748a5789
   = Table 2 (7,339,546 B). Table 2 also gives
   coarse0 77b0cda5...18cd4, coarse1 48ca7775...24b8a, coarse2 418b6d9c...e43e,
   coarse3 8c23427e...6535, mid e97c74dd...be4, fine 9b5b743b...923d,
   fb1 ef85ec73...f215. Without these, R3-R5 can only fail on shape.
2. `commands.json` `outputs` omits every artefact the batch machinery creates:
   the 88 `batches/f<n>.bin` and `batches/done.txt` appear in no command's
   inputs or outputs (`done.txt` appears nowhere at all). A replay driver whose
   file list is derived from `commands.json` cannot know R5's batch targets exist.
   Test:
     python3 -c "import json;d=json.load(open('.scratch/gh/upstream/commands.json'))['children'];
     o=set().union(*[set(v['outputs']) for v in d.values()]);
     print(sum(x.startswith('batches/') for x in o), any('done' in x for x in o))"
   -> 88 True/False pair: 88 outputs under batches/ (all bad*.bin), no done.txt.
3. Table 1 supplies the counts that check a run without the .bin files:
   A 764/774/757/788 (=3083), mid 600, fine 22,379 = 87*256+107 (88 batches),
   initial C 163 unresolved, fallback 1127, final C 282+282+282+281. All
   internally consistent (checked: sums match commands.json's shard counts and
   the 15 nonempty bad files, in C-locale order, match the fallback argv).
Recommendation: R3-R5 compare SHA-256 against Table 2 and counts against Table 1;
gate the non-timing stdout fields, which are also paper-recorded: `xs22829` and
`checked151744086` and `centers249878` (`.scratch/gh/covrun.log` matches Table 1
exactly). Spec §2 says stdout "is not gated"; the two non-timing counts are
recorded data and cost nothing to gate.
