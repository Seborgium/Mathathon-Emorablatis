# N = 112: constraint analysis, cost curve, recommendation

T5 / Parameters, member m2. Every number is printed by a script in `experiments/`
(`n_window.py`, `seedcover_x.py`, `seedcover_y.py`, `n_sweep.py`, `cost_model.py`,
`boxes_k.py`, `pairs_variants.py`, `y_testset_search.py`); CSV tables in `data/`.

The paper's only stated reason for N = 112 is one sentence of §7.3: C(116,5) =
160,389,488 "is below the signed 32-bit limit". That reason does not single out 112.

## 1. The admissible window is [47, 128]

Three inequalities bound N; two are ceilings and one is a floor.

**(a) int8_t on the stored bin differences — the binding ceiling.** §7.3: "All bin
differences lie between −111 and 111; ... The stored five-coordinate differences also
fit the signed eight-bit type used by the cover." A difference of two bins in [0,N−1]
ranges over [−(N−1), N−1], and int8_t holds [−128, 127], so N−1 ≤ 127:

    N ≤ 128.

At N = 112 the largest difference is 111: the paper's quoted "−111 … 111" *is* N−1 for
N = 112, and the headroom to the type limit is 16. This is the only constraint that
explains the size of N, and it is 16 below the type limit — a diet of 87% of what int8
allows. (`n_window.py` §4b.)

**(b) 32-bit arithmetic — a weaker ceiling.** C(N+4,5) < 2^31 gives N ≤ 189
(C(193,5) = 2,118,000,528 < 2,147,483,648; N = 190 gives 2,174,032,288). This bound is
*dominated* by (a): it constrains nothing once the int8 storage is admitted, which is
why it cannot be the reason for 112.

**(c) The fresh-centre floor.** §2.4: "Retaining u as a center would cover the entire
bin with radius 3/(2N) < 0.032", with R = 0.032 fixed by Stage A. So

    3/(2N) ≤ 0.032  ⟺  N ≥ 46.875  ⟺  N ≥ 47,

the fresh-centre radius being 0.031915 at N = 47 (99.7% of R) and 0.013393 at N = 112
(41.9%). Stage A also caps R from above: R_s = 2πR < .203 (A.13) gives R ≤ .203/2π =
0.0323085, so the floor is N ≥ 1.5/0.0323085 = 46.43, still 47.

**Window: 47 ≤ N ≤ 128.** Both bounds are tight in an interesting way: N = 46 fails (c)
by 1.9%, and N = 129 fails (a) by one unit (max difference 128 > 127).

**(d) What does not pin N.** The gap filter (2.8) has thresholds 1−(l−1)/N and
1−(l+2)/N, separated by 3/N against a Lemma 2.5 perturbation of w = 1/N: the ratio is 3
for every N (`n_window.py` §7), so the filter is scale-free. The reuse ball spans
NR = 3.584 bins at N = 112 and 1.504 at N = 47, so reuse gets *easier* as N grows; the
only genuine trade-off is that against enumeration cost, measured next.

## 2. What of the recorded run is reproducible

`experiments/seedcover_x.py` replays the X side exactly as §2.2–2.3 specifies for
N = 112 — weakly increasing 5-bin tuples, the integral orientation filter (2.7)
a ≤ l−d+1, the first midpoint-gap inequality of (2.8), then sumok (2.11) in the residual
direction and in the five directions perpendicular to the unit-exponential columns:

| filter | tuples |
|---|---|
| all weakly increasing 5-bin tuples | 160,389,488 |
| after (2.7) | 85,349,292 |
| after (2.7) and (2.8) first inequality | 16,197,157 |
| after sumok (2.11) | **22,829** |

22,829 is the paper's own "The seed cover retained 22,829 five-bin x lists" (Table 1
caption). It is reproduced **exactly, to the unit** — the strongest check in this note.

**A Table-1 number does not reproduce.** §7.5 reports "Seed cover 151,744,086 pairs". A
pair is an X list with a Y list in the same shared bin, so the total is at most
Σ over the 22,829 X lists of the Y lists in its shared bin. Replaying the Y side (§2.3)
at N = 112 (`seedcover_y.py`, `n_sweep.py`):

* 774,294,080 tails enumerated; 829,306 pass sumok (mean 7,404 per shared bin);
* **112,160,350** pairs survive the stated tests on both sides;
* 171,543,543 survive if the Y side is filtered by the residual direction only;
* **no** subset of the six stated test directions gives 151,744,086
  (`y_testset_search.py`; closest P2+P3 = 149,151,585, 98.3%).

So the printed pair count exceeds what the printed algorithm allows. Either it is taken
before the Y-side sumok test (but then it is ≥ 1.58·10¹¹ unless some unstated Y filter
applies) or it counts a traversal the paper does not describe. **The reproducible
figures are 22,829 X lists, 829,306 Y lists, and ≤ 112,160,350 pairs.**

## 3. The cost curve

Recorded wall clock (§7.5): cover 621.59 s (13.9%), A 2020.32 s (45.2%), B 1071.49 +
407.45 s, C 300.23 + 36.27 s, fallback 8.12 s; total 4470.33 s. Two measured facts:

1. **Cover cost = pair count**, measured exactly for N = 48…128:

   | N | 48 | 56 | 64 | 80 | 96 | 112 | 128 |
   |---|---|---|---|---|---|---|---|
   | pairs | 3,460,356 | 6,192,348 | 10,631,466 | 26,567,283 | 57,772,973 | 112,160,350 | 200,620,232 |
   | X lists | 3,118 | 4,372 | 5,936 | 10,006 | 15,581 | 22,829 | 32,017 |

   A power law fits to P(N) = 0.3426·N^4.154 (0.7% low at N = 112); at the recorded
   5.54 µs per pair that is 621.6 s at N = 112.

2. **Everything else costs one unit per retained centre, and the centre count is flat
   in N.** 112,160,350 pairs collapse to the recorded 249,878 centres: 448.9 pairs per
   centre, against (NR)^d = 200.8 with the measured d = 4.15 — a ball of radius R
   swallows ρ(NR)^d pairs and both the pair count and the ball content grow as N^d, so
   the covering number of the pair set by R-balls is N-independent. Model
   K(N) = 249,878·(P(N)/P(112))·(112/N)^4.154 predicts K ∈ [239k, 261k] across the
   window — flat to ±5%. Cost per centre: 15.40 ms for A + B + C.

The curve is **flat within 15% over the whole admissible window [47,128]**: 3788 s at
the minimum (N ≈ 64) to 5065 s at the ceiling, with 4470 s at N = 112. The cover is not
the bottleneck; A + B + C is 86% of the wall clock and moves with the centre count,
which N barely moves.

## 4. Recommendation

**Keep N = 112 and argue it on the int8 line, not the 32-bit one.** The defensible
sentence is:

> N = 112 was chosen so that the stored five-coordinate bin differences, which range
> over [−111, 111], fit the signed eight-bit type used by the seed cover; the largest
> admissible value is N = 128, and the fresh-centre inequality 3/(2N) < 0.032 requires
> N ≥ 47, so the admissible window is 47 ≤ N ≤ 128. N = 112 keeps 16 units of headroom
> in the difference and a factor 2.4 in the fresh-centre inequality. The cost is flat:
> a measured replay gives 3788 s at N = 64, 4470 s at N = 112 and 5065 s at N = 128,
> so the choice is worth at most 18% of the wall clock either way.

The 32-bit clause should be *deleted* as a justification (it is inert: 189 > 128) or
demoted to a remark that the tuple count also fits 32 bits, with the int8 storage named
as the binding constraint. If a shorter run were wanted, N = 64 saves 15% (measured
pairs 10,631,466 vs 112,160,350) and still keeps 73% of the fresh-centre allowance.

## 5. Halving to 56, doubling to 224

**N = 56.** Nothing breaks. C(60,5) = 5,461,512 (0.25% of 2³¹); max difference 55 (fits
int8 with 72 units of headroom); 3/(2N) = 0.026786 ≤ 0.032 with 16% margin; the replayed
cover gives 4,372 X lists and 6,192,348 pairs (18× fewer), predicted centres 245,574 and
total 3817 s — 15% faster. Costs of the move: the fresh-centre margin falls from 2.4× to
1.19×, all balls double in size (0.0268 vs 0.0134), and the recorded per-seed Stage-A
timings would no longer apply.

**N = 224.** Two type premises fail at once: the max bin difference is 223 > 127 (int8
overflow, so §7.3's storage claim and A.3's "[−111,111]" are both false), and
C(228,5) = 4,912,679,520 = 2.29·2³¹ exceeds the signed 32-bit limit. The cover cost
rises 17.7× to ~11,000 s and the total 3.31× to ~14,800 s with the centre count
unchanged (248,214 predicted): all cost, no coverage. The fresh-centre margin improves
to 4.8×, which nothing needs.
